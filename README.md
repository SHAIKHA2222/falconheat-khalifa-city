# FalconHeat — Khalifa City Urban Heat Intelligence

**Team 971 Liftoff · 813 Challenge · Urban Expansion, Land Use Change & Heat Risk**

[Open the dashboard](https://falconheat-khalifa-city.streamlit.app/)

FalconHeat helps identify where heat-mitigation planning deserves attention within a **defined Khalifa City study area in Abu Dhabi, UAE**. Urban surfaces, limited vegetation and population exposure can combine differently across neighbourhoods; a temperature map alone does not explain those priorities.

The app combines satellite-derived indicators and modeled population estimates in a transparent planning index, explains each polygon's score, and lets users explore hypothetical interventions. The study contains **12 clipped analysis polygons**. It does **not** cover all Abu Dhabi city and its curated boundary is **not an official municipal boundary**.

Do not remove that marker from the public deployment.

## Dashboard walkthrough

1. **Heat Priority:** switch map layers, filter classes/scores, inspect a polygon and its driver contributions. The map and queue share filters. Overview metrics and the polygon inspector use the full study area.
2. **Urban Change:** compare September 2021 and September 2026 NDVI/NDBI. View directional stress flags separately from descriptive changes.
3. **Exposure:** explore modeled residents in analysis polygons and higher-priority areas.
4. **Scenario Lab:** change assumed LST, vegetation, effective exposed-surface share and exposure. This recalculates the index; it is not a physical intervention forecast.
5. **Evidence & Export:** inspect scene IDs and limitations; download all baseline results and provenance/model settings. Filters and scenarios do not alter exports.

## Data and processing

| Input | Published snapshot | Processing / interpretation |
|---|---|---|
| Landsat Collection 2 Level-2 | 24 September 2026 | QA-masked polygon-median surface temperature; STAC scale/offset, Kelvin to °C |
| Sentinel-2 Level-2A | 27 September 2026 | Cloud-masked polygon-median NDVI and NDBI |
| Historical Sentinel-2 Level-2A | 18 September 2021 | Historical indices for the same study polygons |
| ESA WorldCover | 2021 | Fraction of valid pixels classified as built-up (class 50) |
| WorldPop Global2 | 2026 model estimate, 100 m | Estimated residents per polygon; not census counts |
| Study boundary | Curated Khalifa City polygon | Grid partitions clipped to a defined study area |
| Sentinel-1 GRD | Unavailable in bundled snapshot | Optional diagnostic; excluded from score |
| Organizer 813 imagery | Not bundled or used in score | Optional GeoTIFF inspection/preview only |

Source access: [Planetary Computer](https://planetarycomputer.microsoft.com/catalog), [USGS Landsat](https://www.usgs.gov/landsat-missions/landsat-collection-2-level-2-science-products), [WorldPop](https://www.worldpop.org/datacatalog/), [ESA WorldCover](https://esa-worldcover.org/en).

Workflow: acquire catalog items → mask/reproject bands to each polygon → calculate EO indices and temperature → add historical differences and population → normalize indicators → compute contributions and priority → visualize/export.

The acquisition code selects a covering acquisition day within each July–September search window. **These are single-date comparisons, not seasonal multi-date composites.** Matching the seasonal window reduces but does not remove atmospheric, sensor, irrigation or acquisition differences.

The repository contains the team's published EO snapshot and source metadata. No synthetic fallback values are generated by the runtime. Numerical consistency tests and catalog-item checks are not independent validation of every raster-derived measurement. Raw imagery and WorldPop task responses are not bundled. See [validation and limitations](docs/submission_review.md).

## Exact priority formula

For available components:

```text
H = 100 × sum(w_i × component_i) / sum(w_i)
Weights: T 0.35, B 0.20, V 0.15, P 0.15, C 0.15
```

- `T = minmax(lst_c)` across all study polygons.
- `B = minmax(built_up)`; raw `built_up` is a fraction from 0 to 1.
- `V = 1 - minmax(ndvi)`.
- `P = minmax(log1p(population_2026))`.
- `C = 0.5 × clip((-ΔNDVI - 0.02)/0.08, 0, 1) + 0.5 × clip((ΔNDBI - 0.02)/0.08, 0, 1)`.

For min-max normalization, `(x-min)/(max-min)` is used. A constant valid column receives 0.5 because it provides no relative distinction. Missing optional population/change components remain missing and their weights are redistributed. Missing or non-finite core indicators stop analysis. Available but zero change stress retains its weight and contributes zero points.

Only **NDVI loss >0.02 or NDBI gain >0.02** raises a change-stress flag. Negative NDBI change can be substantial without being an expansion flag. The tolerance and weights are **PoC design choices**, not calibrated significance thresholds or learned parameters.

| Displayed score | Planning class |
|---|---|
| 0 to <25 | Low |
| 25 to <50 | Moderate |
| 50 to <75 | High |
| 75 to 100 | Very High |

Scores are rounded to one decimal before classification. Each `contrib_*` column records priority points; their sum rounds to `risk_score`. Legacy column names `risk_score` and `risk_level` refer to planning priority, **not medical risk**. `effective_weights` documents per-row weights. Changing the underlying study area can change normalization and ranks; UI filters do not.

## Example input and output

Published polygon **K10**, near Sector 33 / Post Office:

| Input | Value |
|---|---:|
| Polygon-median LST | 53.53 °C |
| Current NDVI | 0.0507 |
| WorldCover built-up fraction | 0.3634 |
| Estimated residents | 8,157.6 |
| ΔNDVI | +0.0026 |
| ΔNDBI | −0.0382 |

Using the full bundled study area's normalization ranges, output is **57.9/100 (High)**. Its largest contributions are temperature and population. Across the 12 polygons, modeled population totals **97,142**, with **52,781.4** in High/Very High priority polygons. These are snapshot outputs, not independently validated population or health outcomes.

No polygon meets the directional change-stress rule in this snapshot. This does **not** demonstrate that no land-cover change or urban growth occurred.

## Evidence completeness

The historical column `data_confidence` is displayed as **evidence completeness**. It is a heuristic based on scene-level cloud/footprint metadata, population availability and cell clipping. It is not accuracy, uncertainty, a confidence interval, or measured per-polygon valid-pixel coverage. The existing heuristic assigns partial credit to unknown cloud metadata and penalizes edge-cell clipping; both limit its interpretation. A future revision should use actual valid-pixel fractions and independent validation.

## AI and deep learning

The submitted dashboard uses a **deterministic weighted index**, not a trained AI/deep-learning prediction model. “FalconHeat AI” is retained as the existing project name in the interface.

`src/eo_deep_learning.py` is a separate optional DeepLabV3 experiment. Its default checkpoint is not an EO-trained land-cover model; it is not invoked by the dashboard and provides no validated land-cover results. Torch dependencies are deliberately absent from the website requirements. Do not present the experiment as trained or evaluated project performance. Future work: EO-specific training labels, spatially separate validation and class-level IoU/mIoU evaluation.

## Key limitations and next steps

- LST is surface temperature, not air temperature. The anomaly is relative to the median of study-polygon medians, not a rural-reference urban heat-island measurement.
- “Highest polygon-median LST” is not the hottest individual pixel.
- WorldCover 2021 is not a 2026 impervious-surface map; built-up class does not capture all paved surfaces.
- WorldPop represents modeled residents, not daytime occupancy or demographic vulnerability. The index uses resident totals, so unequal polygon sizes affect comparisons.
- NDVI/NDBI are spectral proxies; validate sensor radiometric harmonization, tile overlap and alternative dates before interpreting change as urban expansion.
- No independently validated urban-growth area, heat-health risk, cooling benefit or model accuracy is claimed.
- 813 imagery is not yet integrated into scoring. Check organizer requirements before claiming challenge-data compliance.
- Field/municipal validation, an official boundary, multi-date composites, uncertainty analysis and an EO-trained segmentation model are future development.
